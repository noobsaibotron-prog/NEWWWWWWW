SCOPE (this A/B only — ONE variable = thinPosWeight)
----------------------------------------------------
  - Scale the Thinness OUTPUT gradient ONLY when the Thinness target = 1 (positive sample):
    in trainStep, delta3[Thinness] *= thinPosWeight  IFF problemTargets[Thinness] >= 0.5.
  - Thinness NEGATIVES (target=0) are NOT scaled (constraint #1/#2: no negative amplification).
  - The other 7 classes are untouched; freq-net untouched; DenseLayer::applyGradients UNCHANGED
    (the scaling is at the output-delta level, before backprop).
  - DROP-IN on ml_weights.bin (no architecture change -> file version=1 unchanged).

DESIGN — production training, DEFAULT PRESERVES CURRENT BEHAVIOUR BYTE-FOR-BYTE
------------------------------------------------------------------------------
  - trainStep gains an OPTIONAL float thinPosWeight = 1.0f. Immediately AFTER the existing
    delta3 loop:
        if (thinPosWeight != 1.0f
            && sample.problemTargets[(size_t) ProblemType::Thinness] >= 0.5f)
            delta3[(size_t) ProblemType::Thinness] *= thinPosWeight;
    thinPosWeight = 1.0f => NO scaling => byte-identical to today.
  - trainOnDataset threads an OPTIONAL thinPosWeight = 1.0f to trainStep.
  - KEY SAFETY: default 1.0 == current => the shipped ml_weights.bin and the tests that load it
    (AICorpus, AI-Sweep, BugFixAcceptance) are UNAFFECTED. The param only changes HOW a candidate
    blob is GENERATED (offline/in-test); inference, runtime and audio are NOT touched.
    trainOnDataset(samples, epochs, lr) stays backward-compatible.
  - SIGN NOTE: for a Thinness positive, delta3[Thin] = probScale*(prob - 1) < 0; the update is
    w -= lr*delta3 => the parameter INCREASES (pushes Thinness UP). Scaling that (negative) delta
    by thinPosWeight>1 makes the upward push STRONGER — exactly the intended "more positive signal".
    It does NOT touch the negatives' downward push (those keep target=0, unscaled).
