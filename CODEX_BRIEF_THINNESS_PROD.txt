COUNTER-EXAM REFINEMENTS (2026-06-23 — verified against MLEngine training code)
------------------------------------------------------------------------------
Read of trainStep / trainOnDataset / applyGradients / saveWeights CONFIRMS the
diagnosis: uniform BCE (probScale 1/8, NO class weight, MLEngine.cpp:932); plain SGD
w -= lr*grad (NO weight decay, MLEngine.cpp:101); per-sample, no batch/schedule. Four
additions, BEFORE picking a lever:

  1. BLOCCO 0 = MEASURE FIRST. Instrument trainStep to log the Thinness pre-sigmoid
     logit z3[Thinness] + its gradient norm per epoch across the 3 init seeds. Localize
     the instability signature (oscillation / vanishing gradient / dead ReLU) so the
     lever is chosen on evidence, not guessed. One cause per change.

  2. LEVER ORDER. Diagnosis = variance / seed-instability -> try the VARIANCE REDUCERS
     first: weight decay (1 line in applyGradients) and/or mini-batch gradient averaging
     (trainOnDataset loop). CLASS-WEIGHTING second, and it is TWO DISTINCT LEVERS with
     potentially OPPOSITE-SIGN effects (Codex 2026-06-23):
       - GLOBAL Thinness weight: scale delta3[Thinness] for ALL samples (target=1 AND
         target=0). Because Thinness NEGATIVES outnumber positives, this also amplifies
         the negative push -> can drive Thinness DOWN (UNDERfire).
       - POSITIVE-ONLY Thinness weight: scale delta3[Thinness] only when target=1 ->
         pushes toward detection, risks OVERfire (clean-FP; cf. test-side augment +100
         -> clean-FP 25).
     Which regime applies is EXACTLY what Blocco 0's delta3[Thinness] split by target=1
     vs target=0 measures -> measure before choosing. Any Thinness-boosting lever must
     hold the clean-FP floor (mean<=10 / max<=15).

  3. SERIALIZATION CONSTRAINT. saveWeights = magic 0x4D4C4551 + version=1 + raw floats,
     NO architecture header (MLEngine.cpp:1293). Non-architectural levers (class-weight /
     weight-decay / lr / schedule) are DROP-IN: same format, version stays 1, only float
     values change. A CAPACITY change (bigger hidden) changes the layer sizes -> MUST
     bump the file version + add a loadWeights migration, else shipped installs mis-read
     the blob (silent corruption). Capacity = LAST resort; prefer the drop-in levers.

  4. GATE PREREQUISITE -- candidate-load path. The C1 all-8 gate AND AI-Corpus must load
     the CANDIDATE blob (loadWeights points at a juce::File, e.g. /tmp/candidate.bin),
     NOT the shipped weights -- else the gate measures shipped, not what would ship. Build
     this path first; it also resolves the AICorpusTest "loads shipped weights" caveat
     from the Phase C plan.
