WHY (from Stability1)
--------------------
  - Stability1 (sum-gradient mini-batch): PARTIAL — B=4 lifted the single-blob seed pass-rate
    4/12 -> 6/12 (repro 12/12), but only by rescuing BORDERLINE seeds (22, 303); 6 seeds
    (1,2,3,11,42,202) never pass at any B, each weak on a DIFFERENT class. => SGD variance is PART of
    the cause; the rest is convergence instability of plain SGD on the tiny net (some inits land on
    weak/mal-fit solutions).
  - Dropout is NOT the next lever (Codex): it cuts effective CAPACITY, and the hard seeds already look
    under-capacity; weight-decay (the other classic regularizer) already FAILED (AB2). The indicated
    lever is a better OPTIMIZER, not more regularization.

LEVER (Stability2) — ADAM optimizer (train-only)
------------------------------------------------
  Replace the plain SGD update (w -= lr*grad) with Adam: an adaptive per-parameter step from the 1st
  and 2nd gradient moments. Adam directly attacks gradient-scale imbalance + seed sensitivity — the
  measured "convergence instability" failure mode. TRAIN-ONLY: Adam state (m, v, t) is TRANSIENT,
  NOT saved in the weight blob; inference, the weight FORMAT, and ml_weights.bin are UNCHANGED.
  Default = SGD (byte-identical); Adam is opt-in via a training param.

DESIGN (production training; default preserves SGD byte-for-byte)
----------------------------------------------------------------
  - DenseLayer gains OPTIONAL Adam state (m,v per weight+bias; a shared timestep t) + an Adam apply
    path: m=b1*m+(1-b1)*g; v=b2*v+(1-b2)*g^2; mhat=m/(1-b1^t); vhat=v/(1-b2^t);
    w -= lr * mhat / (sqrt(vhat)+eps), with beta1=0.9, beta2=0.999, eps=1e-8 (standard). SGD path
    UNCHANGED when Adam is off (the m,v buffers are only allocated/used in Adam mode).
  - trainStep / trainBatch / trainOnDataset thread an optimizer choice (SGD|Adam) + Adam lr. Adam and
    mini-batch COMPOSE (Adam applied to the summed mini-batch gradient).
  - NO serialization change (Adam state is not persisted). Drop-in on ml_weights.bin.
