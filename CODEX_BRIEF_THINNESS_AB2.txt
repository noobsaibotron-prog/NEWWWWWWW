SCOPE (this A/B only — ONE variable = lambda)

  - LAYER SCOPE: apply to the PROBLEM-net weights (problemNet_fc1/fc2/fc3) — the net where the

  - DROP-IN on ml_weights.bin (no architecture change -> file version=1 unchanged).

DESIGN — production training, DEFAULTS PRESERVE CURRENT BEHAVIOUR BYTE-FOR-BYTE
------------------------------------------------------------------------------

    w -= lr * (grad + weightDecay * w); for BIASES, UNCHANGED (b -= lr * gradBias).
    weightDecay = 0 reproduces today's blob EXACTLY.
  - trainStep / trainOnDataset thread an OPTIONAL weightDecay (default 0), passed ONLY to the
    problem-net layers' applyGradients; freq-net gets 0.
  - KEY SAFETY: default weightDecay = 0 == current => shipped ml_weights.bin and the tests that
    load it (AICorpus, AI-Sweep, BugFixAcceptance) are UNAFFECTED. The param only changes HOW a
    candidate blob is GENERATED (offline/in-test); the inference path, runtime and audio path are
    NOT touched. trainOnDataset(samples, epochs, lr) stays backward-compatible.

VERDICT: weight-decay is the WRONG lever for Thinness. It SUPPRESSES the weak subtractive class
(Thin 20.7 -> 14 -> 4 -> 0, monotonic) and INFLATES clean-FP (7 -> 20 -> 18 -> 33): shrinking the
problem-net weights drifts outputs toward the (moderately negative, un-decayed) biases, which
still clear the low thresholds => more clean firing. It mildly HELPS the strong classes (Reso/Mud
up) — the opposite of what Thinness needs. Thinness needs MORE signal for its weak positives, NOT
global regularization.
